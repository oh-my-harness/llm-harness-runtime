# Suite A 固定条件重跑：速度、调用量与通过率

更新：2026-09-29 21:48 Asia/Shanghai。负责人：lqj。模型：纯 Qwen2.5-72B 对 `cklxx/laya-browser` v19s + 同一 Qwen。这是作者方案的本地对照扩展，不是 TypeSafe Jev 原模型成绩。

## 可以收敛的结论

**在本次部署和任务范围内，完整两轮均观察到协作方案更快、Qwen 请求更少，验收通过率未下降。** 两轮各 16 题，纯 Qwen 每轮 12/16、协作组每轮 13/16；合计 **24/32（75%）对 26/32（81.25%）**。双方成功的 22 对，速度比为 **1.857 倍**；另看没有 HTTP 失败的 20 个成功配对，仍为 **1.431 倍，节省约 30.1% 时间**。

可以向同事汇报这是支持研究方向的初步证据；不能改写成“已经证明质量等价”“Jev 普遍比 LLM 快”或“决策模型推理能力更强”。独立任务只有 16 个，任务验收较弱，输入编码也不是纯参数消融。

**执行没有全部完成三轮。** 原计划 96 次；有效记录所在的第二次受控运行完成 89 次（含 1 次预算失败），还有 7 次未开始。主表按任务覆盖度提取完整的第 1、2 轮，未按得分选择轮次；第三轮及第一次限流中止记录全部保留，不拼接、补造或冒称 96 次完成。是否追加预算仅用于补完原矩阵，待 lqj 确认。

## 已对齐与保留差异

- 同作者引擎、同 16 题目标、同判空修复、同验收、同 20 步与 180 秒协作式时限；按题和轮次交替先后，每次独立浏览器上下文。时限只在操作边界检查，不能硬中断正在进行的调用，因此有 192.997 秒的失败记录。
- 浏览器显式使用本地 7890 代理；两组 Qwen 通过同一显式 HTTPX 代理 transport，本地 Laya/CDP 直连。Qwen 全部请求统一 `temperature=0`、`top_p=1`、`max_tokens=1024`、JSON 输出。逐请求复核未见路由或参数漂移。未修改系统全局代理。
- 两组同样的 HTTP 429 重试政策：最多三次，等待 30/60 秒，记录并计入墙钟；服务明确返回 `50602 / TPM limit reached`。本次 13 次 429 均由后续重试取得 HTTP 200，但累计等待仍可能使任务超时。官方说明限流按账户和模型计，不能通过换同账户 key 消除。[官方限流说明](https://docs.siliconflow.cn/docs/userguide/faqs/rate-limit-and-upgradation)。
- A 一次合并操作、目标与必要文本；明确合法索引，仅允许整数目标等值转换后校验。B 保留作者默认的输入压缩、截断、分块及文本/下拉 helper。**这比较的是合理部署下的完整方案，不是最终输入相同的模型消融**，不能把所有速度差归给 Laya 参数或架构。
- 本地 Laya 使用 RTX 5070 Ti 16 GiB、BF16 autocast、`fast=False`；Qwen 为 SiliconFlow `Qwen/Qwen2.5-72B-Instruct`，远端硬件与缓存不可控，不是作者本地 Qwen3-8B。Windows、Python 3.13.9、torch 2.11.0+cu128、Laya 0.3.21、transformers 5.17.0、browser-harness 0.1.13。版本来源详见[作者复现报告](laya-browser-author-reproduction-20260929.md)。
- 完整两轮有 27/32 对初始观测散列一致，不能宣称所有网页初态完全相同。原航班题目标为 2026-09-28，运行日在 09-29；没有事后改日期、换题或删除失败。原验收的 URL/标题检查较弱，故这里是验收通过率，不是强语义准确率。
- 工程测试均在本次计时前结束，不再出现前轮测试与实验并行。重跑中不改模型、提示、任务或验收。16 个任务的重复不是 32 个独立任务，不作统计质量等价宣称。
