## 结果核查

- 逐次日志重算与 `report.json`、`attempts.jsonl` 一致；每个开始事件均有结束事件，HTTP 起始事件数与真实调用计数一致。46 次 Qwen 响应均 HTTP 200，返回模型名与指定 Qwen 一致。
- 第二轮全部 19 次非预热 Laya 前向（7 预检 + 12 任务）传输哈希校验通过；状态/指令/选项损失均为 0，候选标记齐全，CPU 回退为 0。任务期峰值已分配显存约 **3.30 GiB**。故障不能归因为本轮再次乱码、静默截断或回退 CPU。
- 7 对初始页面指纹全部一致，Hacker News 初始头条 ID 一致；14 次终末主文档 HTTP 均为 200。只说明本轮这些记录一致，不保证以后公共网站不会变化。
- cross-origin-iframe 上游验收逐 frame 查找 `#out`，会先在无该元素的主 frame 等待 15 秒，再查子 frame；两组均支付这一成本。按预定端到端口径保留，没有事后扣除；它使该题耗时不能简单解释成模型推理耗时。
- A 任务期 Qwen 请求耗时累计 63.092 秒，B 任务期 Laya RPC 累计 1.705 秒。二者调用数和成功率不同，且阶段计量存在嵌套，**不能用这个比值代替端到端有效加速**。

## 初步分析

本轮已确认真实执行和计量链路可以跑通，也观察到本地选择推理耗时较低；但主要问题是动作选择没有可靠推进任务，导致质量条件完全不满足。下一步应先排查 Laya 的任务表达、choice 契约和当前权重的适配问题，区分能力问题与接入误用，再决定是否另开版本验证；目前不能宣称根因已确定。

**不应直接扩大样本、只比较耗时或把结论改写为成功。** 任何后续修正另记版本，保留本轮负结果；不变更既定目标、不增加规则代选、不移除困难任务，也不把原版 Jev 的作者结果冒充本地成果。本轮没有额外调参或补跑。

## 故障复核与修复

Python 原管道实际为 `gbk`、`surrogateescape`，Node 写入为 UTF-8。无模型离线复现中，前三个初态都是可原样往返的 ASCII 内容；select、wikipedia、hacker-news 则无法原样往返，其中 select 产生 7 个代理码点，随后 UTF-8 编码失败。

修复显式指定 Python UTF-8 管道并严格解码；每个真实预测请求附原始 JSON 字符串 SHA-256，Python 先校验再解析、序列化和推理。校验不通过禁止前向。新增真实 Python 子进程测试覆盖中文、符号、重音字符及全部 7 个冻结初态，不加载权重；此类测试只证明通信正确，不算模型成绩。
