# Qwen + Laya 开发对照结果

日期：2026-09-29。负责人：lqj。运行：`miniwob-development-20260929-01`。

**结论：直接动作分工已真实跑通，但当前 Laya 基础权重配置未达到“更快且质量相近”的验证目标。** 在获批的 6 类 MiniWoB++ 任务、每类 2 个固定种子上，Qwen 通过 11/12，Qwen + Laya 通过 1/12。这里只是开发子集，不能代表 Jev 原版、所有 Laya 配置或完整 MiniWoB++ 成绩。

## 条件与意义

- 分工符合已确认目的：B 由 Laya 直接选择操作及目标；只有选中填字才调用 Qwen，8 次 Qwen 请求均为生成，没有规则替代决策或大模型兜底。两组 12 对初始公开输入哈希全部一致。
- 两组共用 120 秒、12 个动作、16 次决策、同一观测/执行器和原生独立验收。只有原生结束且未折扣奖励恰为 1 才通过，部分奖励不算全对。任务对串行，A/B 各 6 次先运行；任务与种子在模型运行前冻结。
- 大模型为硅基流动 `Qwen/Qwen2.5-72B-Instruct`，服务内部版本/硬件未知；Laya 为 `convaiinnovations/laya@55cf4c4`，代码 `9d95567`，2048/1024 输入预算、BF16。未调参追逐结果，未切换 checkpoint，CUDA 无 CPU 回退。
- Windows 11、Ryzen 7 9800X3D（8 核 16 线程）、约 31.16 GiB 可见内存、RTX 5070 Ti（16303 MiB）；Python 3.13.9、PyTorch 2.11.0+cu128、驱动 591.86、Playwright 1.63.0 / Chromium 153.0.8010.12。Qwen 网络等待保留，服务端缓存命中也保留，不能将部署差异全归因于架构。
- 用时从任务环境就绪后的首次观测前到独立验收结束；包括输入审计、模型、工具及原生终止检查。浏览器准备/清理另计，两组分别共 5.88/5.83 s；共享初态审计 10.16 s、Laya 加载 0.817 s、预热 0.311 s 单列，不混入单题提速。
- 运行记录墙钟为 74.62 s，覆盖初态审计、模型加载预热和全部尝试；计时止于汇总写入及 HTTP 服务关闭之前，不冒充完整进程退出耗时。若把各次浏览器准备/清理也纳入成功任务摊销，A 为 4.305 s、B 为 15.612 s。
- 实际共 36 次 Qwen 请求，输入/输出分别为 A 45178/288 token、B 1764/72 token。全部请求有 usage，无 API 自动重试。没有把重复选择重新调用生成模型算成网络重试。

这轮最有价值的发现是：**单次决策快，并不意味着完整 Agent 更有效；状态变化后的重复选择会同时损害质量和调用效率。** 当前证据支持继续定位输入适配、重复选择及无害输出字段的协议处理，不支持直接扩大到正式性能结论。下一版改动先明确、单独冻结，旧负结果保留；更换权重或微调需另行确认。
