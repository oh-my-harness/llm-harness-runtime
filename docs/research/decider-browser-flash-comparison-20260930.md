# 约 2B 决策模型替换：Flash / Laya / Decider 三组对照

实验日期：2026-09-30 11:48–12:06 Asia/Shanghai。负责人：lqj。

## 目的与结论

**验证 Jev 式决策与必要生成的协作能否更快，并保持相近的完整任务通过率。** 在 lqj 确认“那你试试看”后，加入约 2B 的开放决策模型，同时重跑纯 Flash 和原 Laya 对照；不改研究目标，不把普通小型生成模型冒充 Jev，不混用昨天的成绩。

**16 题 × 3 组 × 2 轮，96/96 次尝试全部完成，没有补跑或中途调参。当前替换结果为负：Decider-2B 没有改善速度或通过率。**

| 核心指标 | A：纯 Flash | B：Laya+Flash | C：Decider-2B+Flash |
| --- | ---: | ---: | ---: |
| 决策模型规模 | 远端 Flash | 约 0.322B | 1.882B |
| 第 1 / 第 2 轮通过 | 13/16 / 14/16 | 11/16 / 13/16 | 7/16 / 6/16 |
| 合计通过率 | **27/32，84.375%** | **24/32，75%** | **13/32，40.625%** |
| 全部尝试累计用时 | **287.723 秒** | **217.522 秒** | **583.634 秒** |
| 工具执行尝试 | 105 | 110 | 430 |
| Flash HTTP 请求，含重试 | 139 | 10 | 65 |
| 本地决策请求 / 实际前向 | 0 / 0 | 141 / 158 | 447 / 518 |

C 比 B 少通过 11 次，累计用时为 B 的 **2.683 倍**、A 的 **2.028 倍**。B 本次耗时比 A 少 24.4%，但少通过 3 次，也不能宣布同时满足相近质量和提速。此前 Flash 两组均 26/32 的历史结果仍成立于原场次，本轮不覆盖它。

**可以得到的结论是：在本轮固定浏览器方案和部署条件下，直接换成这个约 2B 的决策模型没有收益，不能把 Laya 的不足简单归因于参数小。** 这不是同一模型家族的规模消融，更不能推出所有 2B 模型都更差，或原版 TypeSafe Jev 不有效。

## 分工与候选

候选仍由浏览器框架读取网页 DOM、结合支持的操作产生，**不是 Flash 预先生成一套答案供小模型选择**。

- A：Flash 一次选择动作、目标并生成必要字段文本；下拉值也合并在该决策中。
- B/C：Laya 或 Decider 直接选择动作、目标与继续/结束；Flash 按需生成字段文本、辅助下拉值，执行器和验收相同。
- 本轮 B 的 Flash 请求为 **8 次字段文本 + 2 次下拉辅助**；C 为 **63 次字段文本 + 2 次下拉辅助**。C 更多地选择填写操作，间接增加了生成请求，不是额外加入了大模型代选。
- 沿用作者的候选处理、输入压缩和 undo 保护；没有新加任务规则、规划器、升级大模型代选、LLM 完成检查或宏。

## 条件与适配边界

| 项目 | 固定条件 |
| --- | --- |
| 文本模型 | 官方 `deepseek-flash`，`https://api.deepseek.com`；三组显式非思考模式，temperature=0、top_p=1、max_tokens=1024、JSON 输出 |
| B 权重 | `cklxx/laya-browser` v19s，mmBERT-base，约 0.322B；快照 `645cf366a2ae35f1086e8c20eff48f909bb49206`，原 1024/768 输入预算、`fast=False` |
| C 权重 | `Mapika/decider-2b` v11，实载 **1,881,825,088** 参数；快照 `533964dae8be954c5b5e19fa4948e48408094c1e`，使用该快照随附的作者推理代码 |
| C 推理方式 | 原生 plain/state-first、独立问题行、发布温度；一次前向读取候选分数，不做文本解码；BF16/CUDA eager，无编译、CUDA 图或 schema 缓存 |
| B/C 共同包装器 | 保留作者网页 1200 字符摘要、候选压缩、60 项分块及 helper；C 采用自己的原生分词/编码，不额外扩大网页观测或删减候选 |
| 输入差异 | C 原生 state token 上限 32768，实际问题行最多 2042 tokens，超限会报错；与 B 不同的编码及预算是方案差异，不声称输入逐 token 相同或仅改变参数量 |
| 单候选兼容 | 作者原生接口拒绝单候选；最小适配保留唯一真实选项并通过原打分路径实际前向，不造第二选项、不绕过模型。多候选与原生接口数值一致的预检通过；正式场次累计 201 个单候选问题行 |
| 任务与执行器 | 原作者 Suite A 全部 16 题、目标及验收不变；引擎 `browser-use/jev-ultrafast@1231850a` 加原作者补丁，共用原有空值修复；`author_control.py` 未改 |
| 顺序与隔离 | 同场串行交错；保留原 A/B 相对交替顺序，C 在首/中/末轮换；每次独立浏览器上下文。两种本地权重同时驻留 GPU，没有并行推理或并行工程测试 |
| 环境 | Windows，RTX 5070 Ti 16 GiB；Python 3.13.9、torch 2.11.0+cu128、transformers 5.17.0、Laya 0.3.21、browser-harness 0.1.13；同一 headless Chromium 1243、1120×780 |
| 网络与预算 | 浏览器和 Flash 经本地 7890 代理，本地模型/CDP 直连；25 秒 HTTP 超时，20 步、120 决策、180 秒协作式边界时限；Flash HTTP 总上限 237，实际 214 次；原重试设置未改 |

C 是独立的开放决策模型，**不是“Laya-2B”或 TypeSafe Jev 权重**。参数、架构与训练背景见[固定模型卡](https://huggingface.co/Mapika/decider-2b/blob/533964dae8be954c5b5e19fa4948e48408094c1e/README.md)；作者明确其浏览器验证只覆盖 click-only MiniWoB++，未测试填写、滚动或真实网站，见[固定源码说明](https://github.com/Mapika/decider/blob/f42a043b15a99a872bd625a9fc3a2cbd791c5ee4/README.md)。这里评估的是迁入既有浏览器方案后的效果，不把上游分数当本次预期成绩，也不恢复 MiniWoB++ 实验路线。

**速度限制：** 当前 Windows 环境缺少 `causal-conv1d` / `flash-linear-attention`，C 使用 PyTorch 参考实现；记录的是本机部署速度，不代表作者优化后的最佳速度。工程预检已核对权重散列、原生多候选一致性、单候选实际前向和 CUDA 设备；接口一致不意味着浏览器决策质量已保证。

## 解释范围与证据

- **不是参数量的因果结论。** Laya 是浏览器专用权重，Decider 的架构、训练、分词和推理实现不同。现在支持“不建议直接用该 C 配置替换 B”，不支持“增大模型一定无效”；任务适配、停止判断和实际部署内核都需与参数量分开考虑。
- **不是质量等价检验。** 只有 16 个独立任务、重复两次，没有预注册非劣界限。页面动态变化，A/B、A/C、B/C 初态散列分别为 24/32、27/32、29/32 相同；不能保证每次遇到逐字一致的页面。
- **验收能力有限。** 沿用作者终态验收并要求无运行错误、复选框实际为 true，本次主验收与作者计分全部一致；部分题只检查 URL/标题，不等于强语义准确率。航班日期仍为已过期的 2026-09-28，不据该题评价模型能力。
- **不混淆复现层次。** 本轮是固定 Laya 作者浏览器框架上的模型替换与自建纯 LLM 对照，不是 Decider 官方整套浏览器实验复现，也不是 TypeSafe Jev 原模型成绩。
