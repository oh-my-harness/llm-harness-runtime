# Suite A：纯 Qwen 与 Laya+Qwen 开发对照

更新：2026-09-29 20:51 Asia/Shanghai。负责人：lqj。运行：`laya-browser-paired-20260929-01`。定位：基于作者任务的本地对照扩展，不是作者原生 A/B，也不是 TypeSafe Jev 原模型成绩。

## 结论先行

后续已完成显式代理、公共生成参数统一后的[固定条件重跑](laya-browser-controlled-comparison-20260929.md)，以该报告作为当前进展入口；本页保留前轮原始条件与成绩，不覆盖历史。

按 lqj“先跑对照实验”的要求，同一 16 个任务、同一引擎上的 **32 次尝试全部完成**。主要验收口径下，纯 Qwen 为 **10/16（62.5%）**，Laya+Qwen 为 **12/16（75.0%）**；双方均成功的 9 对，累计任务时间为 **98.929 秒对 62.166 秒，A/B = 1.591 倍，协作组少用约 37.2% 时间**。

这是值得继续验证的初步信号：本轮协作方案更快、实际大模型请求更少，观察到的通过率未下降。但**不能据此宣布质量等价或 Laya 推理能力优于 Qwen**：每题仅一次，存在网页失败、一次远端超时、输出协议校验失败和验收强度限制。两组比较的是完整方案，输入处理也不同。

此前原样单组的 [13/16 记录](laya-browser-author-reproduction-20260929.md)完整保留。本轮两组共用空值修复并重新运行，不能拿旧单组结果拼接成新对照。

## 失败与验收复核

- 作者补丁的 `undo=None` 调用缺陷在两组统一修复；**本轮没有 TypeError**。B 的两道图书题仍失败，均执行到 20 步上限，说明修好崩溃不能直接推定任务成功。原规则仍过滤重复动作，没有人为选正确目标。
- A 的 dropdown、checkbox 在目标校验处退出，flights 在操作校验处退出。原始异常栈位置已经记录；但本轮只保存了成功解析的 Qwen 决策，**被拒绝的响应原文未保存**，因此无法进一步区分目标类型不符、索引不在候选内或具体错误操作。按协议失败计入结果，不将这些失败包装为已确证的推理能力差距。
- A 的 checkbox 实际已勾选，原作者验收为通过；但随后目标校验错误退出。按运行前固定的“验收通过且无运行错误”口径，主要分数仍计失败。若只看作者终态验收，A 为 11/16、B 为 12/16，差异是 +6.25 个百分点，而不是 +12.5。
- B 的 checkbox 初始观测为 `chrome-error://chromewebdata/`；A 的 quotes 在初始阶段报 OSError，未发生模型调用，缺少构造阶段的完整栈，不能断言唯一根因。A 的 hn-past 最后一次 Qwen 请求 ReadTimeout 为 25.172 秒，计入失败和实际调用，用量未知。这些不是纯模型能力失败。
- 两组都未完成 flights；原题日期为 2026-09-28、运行日为 09-29，未改日期或换题。作者其他 URL/标题/文本验收较弱，故本表是共用验收下的开发通过率，不是逐项语义要求都经过强验证的准确率。

## 实验条件

决策权重为 `cklxx/laya-browser` v19s，固定快照 `645cf366a2ae35f1086e8c20eff48f909bb49206`；作者来源与环境详情见[原样复现报告](laya-browser-author-reproduction-20260929.md#对齐依据与条件)。引擎为 `browser-use/jev-ultrafast@1231850a0bf1a0c0341fe408ef1668dbbfdfac46` 加作者发布补丁，唯一公共策略修复是判空。原始上游副本未再改动，修复通过同一个运行时子类应用于 A、B。

- 两组文本/生成模型均为 SiliconFlow `Qwen/Qwen2.5-72B-Instruct`，不是作者本地 Qwen3-8B-AWQ。A 的新决策提示复用作者动作规则，temperature=0、max_tokens=1024，操作/目标/文本一次 JSON 返回；B 保留作者 helper 配置。A 输出只映射到观测候选，没有规则代选或大模型回退。
- A 不请求 Laya 决策，实际前向为 0；Laya 为整场 B 任务预先加载并驻留。B 本机 RTX 5070 Ti 16 GiB、驱动 591.86、BF16 autocast、`fast=False`、未启用 TileLang。Windows、Python 3.13.9、torch 2.11.0+cu128、Laya 0.3.21、transformers 5.17.0、browser-harness 0.1.13、headless Chromium 153.0.8010.12；视口沿作者 1120×780。
- 同 16 题原顺序、各一次，A/B 和 B/A 按题交替；每次独立浏览器上下文。最多 20 个已执行步骤、底层 120 次决策、180 秒协作式边界检查；整场 Qwen HTTP 上限 120。该时限不能硬中断正在进行的浏览器或模型调用，本轮未触发。
- 两组获得同一框架的观测与候选来源；A 读取完整可见表和文本，B 沿用作者压缩、截断及宽候选分块。**输入编码与生成分工不同，是整体方案对照，不是只替换参数、固定最终模型输入的消融。** A 可合并生成，B 的下拉值 Qwen 辅助按作者默认保留。
- 12/16 对的初始观测散列一致；wiki-einstein、checkbox、quotes、hn-past 不一致（quotes A 未取得初始观测）。公开网站会漂移，网络/缓存不能视为恒定。服务端缓存已知命中 token 为 A 15,968、B 128，没有假称关闭缓存。
- **资源干扰披露**：20:31:13 至 20:31:28 运行了离线 Python 回归，和首对任务有资源重叠，这是执行安排不足。主结果不删该对；排除首对的敏感性结果为其余 8 个双方成功配对 **1.538 倍**，方向不变。后续计时轮必须与工程测试串行。
