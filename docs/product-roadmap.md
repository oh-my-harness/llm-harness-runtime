# 产品路线图

> 面向产品经理、技术选型者和最终用户。用非技术语言说明 runtime 当前能做什么、下一版本会做什么。
> 技术细节见 [runtime-framework.md](runtime-framework.md)。

---

## 这个项目是什么

**llm-harness-runtime** 是一个 AI Agent 运行时——你可以把它理解成 AI Agent 的"操作系统"。大语言模型（LLM）本身只会对话，不能执行命令、读写文件、调用外部 API。运行时给 LLM 装上手脚和眼睛，让它变成能完成实际任务的 Agent。

你可以把运行时想象成一个工作台：

- **模型**是坐在工作台前的人——负责思考、决策
- **工具**是工作台上的工具——文件读写、命令执行、网络请求等
- **运行时**是工作台本身——管理工具怎么摆放、安全围栏怎么设、上下文怎么传递、多个 Agent 怎么协作

运行时不包含任何特定领域的逻辑（比如不会内置"写代码的规则"或"做客服的话术"），它只提供通用基础设施。具体怎么用，由上层应用决定。

## 当前能力一览

### 🟢 已可使用

#### Agent 核心循环

Agent 的工作方式是"思考→调用工具→看结果→再思考"的循环。运行时实现了这个循环，并且支持：
- **重试与退避**：当 API 调用失败（如限流、超时），自动等待后重试，等待时间指数增长 + 随机抖动（防止多 Agent 并发重试时"惊群"）
- **流式输出**：模型的回复可以边生成边展示，用户不用等全部生成完才看到
- **中止/取消**：用户或程序可以随时中止当前运行，中止信号会传播到所有子任务

#### 工作流引擎

复杂任务往往不是一轮对话能完成的。运行时支持定义多步骤工作流：
- **分阶段执行**：把任务拆成多个阶段，每个阶段有不同的工具和指令
- **条件跳转**：根据上一步结果决定下一步走哪条路
- **崩溃恢复**：运行时持久化每一步的状态，进程崩溃后可以从断点恢复，不用从头来

#### 文件编辑

Agent 可以像人类编辑器一样操作文件：
- **读取**：支持按行范围读取，自动加行号，避免读入超大文件
- **编辑**：基于行号定位修改，带"快照标签"防止改到过时的内容
- **写入**：创建或覆盖文件

#### 搜索工具

Agent 在大型代码库里找东西时，需要搜索工具：
- **grep**：按内容搜索（"找到所有包含 TODO 的文件"）
- **glob**：按文件名模式搜索（"找到所有 .rs 文件"）

跨平台专用搜索工具，不依赖 bash，有安全限制。

#### 工具系统

运行时有一套完整的工具管理机制：
- **工具注册**：应用层注册自定义工具，Agent 自动发现并使用
- **并行执行**：同一轮里多个独立工具调用可以并行跑，不串行等待
- **输出投影**：工具返回大结果时可以只给模型看摘要，完整结果留作后用
- **输出截断**：工具输出过长时自动截断（`ToolOutputGuardHook`），超长内容持久化到文件，模型只看到摘要 + 文件路径

#### 沙箱隔离

Agent 执行命令（特别是 bash）时需要安全隔离。运行时提供沙箱：
- **Linux**：bubblewrap 沙箱
- **macOS**：seatbelt 沙箱
- **跨平台**：OS 原生执行 + 路径限制

每种沙箱限制文件访问范围和系统调用权限，防止 Agent 意外破坏宿主环境。

#### 成本与预算

运行 LLM 要花钱。运行时内置成本管理：
- **用量追踪**：自动记录每次 API 调用的 token 消耗和 USD 成本
- **预算上限**：设置花费上限，超限自动停止
- **多模型明细**：按模型分别统计，支持混合模型场景

#### 子 Agent 协作

复杂任务可以拆给多个 Agent 并行做：
- **派生**：主 Agent 可以派生子 Agent（`spawn_agent` 工具或 `HarnessSubAgentSpawner` API），分配独立任务
- **通信**：主子 Agent 之间可以互发消息、等待回复（MessageBus 消息路由）
- **查询**：主 Agent 可以查询子 Agent 的状态（含角色描述，如"代码审查员"）
- **中止**：主 Agent 可以中止子 Agent
- **并发上限**：`max_concurrent` 限制同时在飞的子 Agent 数
- **配置定制**：`SpawnOptions` 支持 provider 继承/别名、context 传递（父对话摘要/文件/用户指令）、system prompt 与 thinking level 覆盖；`builder_customize` 闭包为所有子 Agent 统一注入插件
- **完成通知**：`SpawnPlugin` 把子 Agent 完成事件接回主 Agent 的通用 hook 流（空闲时唤醒主 Agent 继续）

#### 多 Agent 团队（Agent Team）

去中心化的多 Agent 协作（`llm-harness-agent-team`）：
- **声明式组队**：`IndividualSpec`（id/专长/模型/反思间隔）→ `AgentTeam::build` 物化为自驱动 runner
- **P2P 社交工具**：`delegate_task`（任务委派路由）、`send_message`、`broadcast`、`search_contacts`（通讯录搜索）、`set_reminder`
- **操作员交互**：人类通过 `AgentTeam::submit` 派活、`AgentTeam::receive` 收结果
- **团队记忆**：SQLite 团队记忆（`TeamSqliteMemoryStore`），反思循环把可复用经验沉淀下来，跨进程重启存活

#### Agent Inspector（调试观测）

开发者的 Web 调试工具（`llm-harness-inspector`）：
- **实时事件流**：WebSocket 推送全部 agent 事件（含逐 token 流式），首条快照 + 增量透传
- **REST 端点**：配置快照、当前 session 历史、token/成本用量、skill 列表
- **交互端点**：运行中可注入 steer 消息、中止当前 turn、发起新 prompt（human-in-the-loop）
- **内置 Web UI**：单文件 HTML，`SENZA_INSPECT=8080` 环境变量即可给任何 agent 挂上调试界面

#### 网络工具

- **web_search**：9 个搜索 provider（DuckDuckGo 免 key 默认、Bing、Brave、Tavily、Serper、SerpAPI、Exa、SearXNG、Google CSE）
- **web_fetch**：抓取网页并提取可读文本
- **code_exec**：临时目录中执行 Python/Bash/JavaScript 代码片段，继承沙箱与 abort 传播

#### 多模态

Agent 可以看图、读 PDF：
- **图片**：用户消息和工具结果都可携带图片（base64 或 URL），`read` 工具读图片文件时返回真实图片块
- **PDF 文档**：`ContentBlock::Document`，base64（Anthropic 协议）与 URL（智谱系网关）两种路径，端点能力差异由 provider 层处理

#### 持久状态

运行时把状态持久化到磁盘，支持：
- **任务存储**：每个任务的执行记录可保存
- **检查点**：关键节点可存检查点
- **崩溃恢复**：进程意外终止后可从检查点恢复

#### 规划能力

Agent 可以先制定计划再执行。运行时提供规划工具，Agent 可以：
- 生成结构化计划
- 按计划分步执行
- 根据执行结果调整后续步骤

#### 安全规则集

开箱即用的危险命令防护：
- **命令黑名单**：拦截 `rm -rf`、`sudo` 等危险命令
- **路径遍历防护**：阻止 `cd ../../etc` 等路径逃逸
- **注入短语过滤**：默认拦截常见提示注入模式（中英文），过滤工具返回和上下文中的恶意指令

#### 通知

Agent 能主动通知用户重要事件：
- **通知工具**：`notify_user` 内置工具
- **通知通道接口**：`NotificationChannel` trait，应用层可实现 IM/邮件/短信等渠道

#### 状态栏

Agent 运行时，用户能看到当前状态：
- **状态栏模板**：开箱即用的状态栏格式，收集当前任务、花费、预算剩余、待办事项等
- **TODO 工具**：内置待办列表工具（`todo_write`：rewrite/update/add/clear 四种动作），Agent 能维护多步骤任务进度，不会在压缩时丢失

#### 上下文压缩

对话太长时，模型装不下全部历史，需要压缩：
- **自动检测**：上下文超限时自动触发压缩
- **可自定义 prompt**：压缩策略可配置（context-aware compaction prompt template）
- **熔断器**：连续失败几次才停止，API 偶尔故障不会导致整个 Agent 终止

#### 项目指令文件

Agent 启动时自动读取项目指令文件：
- **自动扫描**：读取 `CLAUDE.md`、`.cursorrules` 等文件
- **注入系统提示词**：项目规则自动注入，不用每次告诉 Agent

#### 上下文来源标注

每段内容标注来源，防止工具返回里的恶意指令误导 Agent：
- **来源标签**：工具返回内容自动包裹 `<external_content>` 标签
- **来源约束**：模型能区分用户指令和工具返回

#### Skill 系统

Skill 是预定义的能力包——一段提示词 + 配套工具：
- **加载与解析**：Skill 的加载、解析、读取工具都实现了
- **自动注入**：Skill 列表自动注入到模型上下文，模型知道自己有哪些能力包

#### 事件驱动

Agent 可以等事件触发：
- **事件流接口**：`EventStream` trait + 等待工具，支持超时
- **内置实现**：定时器（Timer）、心跳（Heartbeat）、Webhook、Shell 进程监控
- **事件过滤**：`FilterStream` 按来源/渠道/字段过滤事件
- **事件模板**：默认事件 payload 模板

#### 故障恢复

Agent 运行中会遇到各种故障，运行时提供多层防护：
- **退避抖动**：重试等待加随机抖动，防止多 Agent 并发"惊群"
- **连续失败计数**：同一工具连续失败 N 次自动停止（FailureCircuitBreaker）
- **死亡螺旋防护**：错误循环时禁用副作用操作（DeathSpiralGuard）
- **重复调用检测**：同一工具同一参数反复调用时提醒（RepetitionGuard）
- **全局轮数上限**：max_turns 安全阀，防止 Agent 无限循环
- **截断续写**：模型回复被截断时自动续写（TruncationContinuation）

#### 持久记忆防线

防止恶意内容被写入持久记忆：
- **跨会话写入审查**：`memory_write` 和文件写入操作扫描注入短语
- **检测即拦截**：恶意内容被拦截，不会被写入长期记忆

#### MCP 集成

MCP（Model Context Protocol）是一个开放协议，让 Agent 连接外部工具服务：
- **基本可用**：Agent 可以通过 MCP 协议调用外部工具
- **版本锁定**：锁定 MCP 服务器版本，外部服务更新不改变 Agent 行为
- **凭证作用域**：`McpCredentialGuardHook` 检查工具调用的凭证权限

#### 工具耗时标注

慢工具让模型感知执行时间，便于决策：
- **opt-in 附加**：`bash`、`code_exec`、`web_search`、`web_fetch` 的结果末尾自动附 `[duration: ...]`（成功与失败均携带）
- **hook 无感**：标注在 after-hook 决策落地之后附加，hook 看到的是无标注结果

#### 策略层独立

策略代码已提取到独立 crate（`llm-harness-strategy`），编译器强制机制/策略边界：
- 安全规则、loop 安全、状态栏、通知、注入过滤、压缩策略、事件流等均为策略层
- 机制层（runtime/types/loop/agent）不包含策略逻辑

### 🟡 部分支持（有基础，缺默认配置）

#### 工具审批

Agent 要执行有风险的操作（删文件、跑 bash 命令）时，应该有人把关。

**已有**：审批框架完整——应用层可以定义"什么工具什么参数需要批准"的规则，Agent 调用工具前会先过一遍规则。安全规则集已提供默认危险命令拦截。
**缺失**：没有通用的"人工确认"内置工具。应用层可以基于审批 Hook 自己实现，但没有开箱即用的 `request_human_approval`/`request_human_input`。

#### 审计日志

Agent 做了什么操作、调了什么工具、花了多少钱——这些需要记录留痕。

**已有**：审计框架完整，记录带 SHA-256 哈希链，防篡改。
**缺失**：没有默认的结构化日志格式。应用层要自己定义日志长什么样。下一版本会提供默认模板。

#### 子 Agent 配置继承

**已有**：派生、通信、查询（含角色描述）、中止、并发上限功能完整；`SpawnOptions` 可覆盖 system prompt 与 thinking level，`builder_customize` 闭包可为所有子 Agent 统一注入插件。
**缺失**：子 Agent 不自动继承父 Agent 的工具列表。子 Agent 默认使用 `sub_plugin_factory` 提供的工具集，需要按需配置。

### 🔴 待实现

#### HITL（人机协作）

有些操作需要人类确认后才能执行（"可以删除这个文件吗？"），有些需要人类提供输入（"这个变量叫什么名字？"）。

当前运行时没有内置的人机协作工具。应用层可以基于工具审批 Hook 自己实现，但没有开箱即用的方案。下一版本会提供 `request_human_approval` 和 `request_human_input` 两个内置工具，支持超时自动降级（没人响应时按默认策略处理）。

#### 主动工具发现

当工具数量很多时（几十甚至上百个），全量塞给模型会导致提示词过长、模型选择困难。

当前运行时全量注入所有工具描述。下一版本会加 `discover_tools` 元工具——Agent 先搜索可用工具，只加载相关的。但短期内（数十个工具）全量注入仍然够用。

#### 空闲看门狗

流式输出时如果模型卡住不输出，Agent 会一直等。下一版本会加看门狗，模型不输出时自动超时。

#### 消息不可压缩标记

关键消息（重要决策、用户指令）不能被压缩丢弃。下一版本会支持标记某些消息为"不可压缩"。

#### 命令语义分析

分析 bash 命令的真实意图，做更精准的安全判断，不只靠字符串匹配。下一版本会提供。

#### 批量消息编号

多条消息合并时加序号，Agent 不会遗漏批量消息。下一版本会提供。

#### 工具描述审查

MCP 工具描述可能包含提示注入。当前有凭证作用域检查，但不对描述文本做注入审计。下一版本会加审查机制。

#### 工具层次化组织

工具分类分组，大量工具时的组织管理。下一版本会提供。

#### 持久化终端会话

Agent 跑 bash 命令时，每条命令都是独立的——`cd /tmp` 在下一条命令里不生效。要维持会话状态（当前目录、环境变量），需要持久化终端。

当前运行时每次执行 `sh -c` 新建进程。持久化终端需要 PTY 管理和长运行 shell 进程，实现复杂。暂不计划实现。

#### 流式工具执行

当前 Agent 等模型把整条回复全部生成完，才开始执行工具。如果模型在一条回复里调了多个工具，要等全部生成完才能执行第一个。

流式工具执行可以在模型生成到工具调用时立即开始执行，减少等待。但实现复杂（需要流中增量解析工具调用），暂不计划实现。

## 明确不做的事

| 不做 | 理由 |
|------|------|
| 流式工具执行 | 实现复杂度高，收益有限。当前"生成完再执行"的模式对大多数场景够用 |
| 持久化终端会话 | 需要 PTY 和长运行进程管理，复杂度高且安全风险大 |
| 写入后自动 lint | 运行时提供机制（Hook），但不内置 linter。应用层可自行接入 |
| 动态工具描述 + KV Cache 优化 | 当前数十个工具全量注入足够，优化收益不明 |
| 中途转向（mid-turn steer） | 基础 steer 队列已实现（`Agent::steer`，Inspector 的 `/api/inject` 也走它）；更复杂的 mid-turn 打断暂不做 |
| 优先级消息队列 | 太复杂，当前消息按序处理足够 |
| 多渠道通知 | 先做单通道通知，多渠道（邮件+短信+IM）是应用层的事 |
