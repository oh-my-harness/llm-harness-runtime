# 产品路线图

> 面向产品经理、技术选型者和最终用户。用非技术语言说明 runtime 当前能做什么、下一版本会做什么。
> 技术细节见 [ROADMAP.md](ROADMAP.md)。

---

## 这个项目是什么

**llm-harness-runtime** 是一个 AI Agent 运行时——你可以把它理解成 AI Agent 的"操作系统"。大语言模型（LLM）本身只会对话，不能执行命令、读写文件、调用外部 API。运行时给 LLM 装上手脚和眼睛，让它变成能完成实际任务的 Agent。

你可以把运行时想象成一个工作台：

- **模型**是坐在工作台前的人——负责思考、决策
- **工具**是工作台上的工具——文件读写、命令执行、网络请求等
- **运行时**是工作台本身——管理工具怎么摆放、安全围栏怎么设、上下文怎么传递、多个 Agent 怎么协作

运行时不包含任何特定领域的逻辑（比如不会内置"写代码的规则"或"做客服的话术"），它只提供通用基础设施。具体怎么用，由上层应用决定。

## 当前能力一览

### 🟢 已可使用

#### Agent 核心循环

Agent 的工作方式是"思考→调用工具→看结果→再思考"的循环。运行时实现了这个循环，并且支持：
- **重试与退避**：当 API 调用失败（如限流、超时），自动等待后重试，等待时间指数增长
- **流式输出**：模型的回复可以边生成边展示，用户不用等全部生成完才看到
- **中止/取消**：用户或程序可以随时中止当前运行，中止信号会传播到所有子任务

#### 工作流引擎

复杂任务往往不是一轮对话能完成的。运行时支持定义多步骤工作流：
- **分阶段执行**：把任务拆成多个阶段，每个阶段有不同的工具和指令
- **条件跳转**：根据上一步结果决定下一步走哪条路
- **崩溃恢复**：运行时持久化每一步的状态，进程崩溃后可以从断点恢复，不用从头来

#### 文件编辑

Agent 可以像人类编辑器一样操作文件：
- **读取**：支持按行范围读取，自动加行号，避免读入超大文件
- **编辑**：基于行号定位修改，带"快照标签"防止改到过时的内容
- **写入**：创建或覆盖文件

#### 工具系统

运行时有一套完整的工具管理机制：
- **工具注册**：应用层注册自定义工具，Agent 自动发现并使用
- **并行执行**：同一轮里多个独立工具调用可以并行跑，不串行等待
- **输出投影**：工具返回大结果时可以只给模型看摘要，完整结果留作后用

#### 沙箱隔离

Agent 执行命令（特别是 bash）时需要安全隔离。运行时提供沙箱：
- **Linux**：bubblewrap 沙箱
- **macOS**：seatbelt 沙箱
- **跨平台**：OS 原生执行 + 路径限制

每种沙箱限制文件访问范围和系统调用权限，防止 Agent 意外破坏宿主环境。

#### 成本与预算

运行 LLM 要花钱。运行时内置成本管理：
- **用量追踪**：自动记录每次 API 调用的 token 消耗和 USD 成本
- **预算上限**：设置花费上限，超限自动停止
- **多模型明细**：按模型分别统计，支持混合模型场景

#### 子 Agent 协作

复杂任务可以拆给多个 Agent 并行做：
- **派生**：主 Agent 可以派生子 Agent，分配独立任务
- **通信**：主子 Agent 之间可以互发消息、等待回复
- **查询**：主 Agent 可以查询子 Agent 的状态
- **中止**：主 Agent 可以中止子 Agent

#### 持久状态

运行时把状态持久化到磁盘，支持：
- **任务存储**：每个任务的执行记录可保存
- **检查点**：关键节点可存检查点
- **崩溃恢复**：进程意外终止后可从检查点恢复

#### 规划能力

Agent 可以先制定计划再执行。运行时提供规划工具，Agent 可以：
- 生成结构化计划
- 按计划分步执行
- 根据执行结果调整后续步骤

### 🟡 部分支持（有基础，缺默认配置）

#### 工具审批

Agent 要执行有风险的操作（删文件、跑 bash 命令）时，应该有人把关。

**已有**：审批框架完整——应用层可以定义"什么工具什么参数需要批准"的规则，Agent 调用工具前会先过一遍规则。
**缺失**：没有开箱即用的默认规则。比如"rm -rf"应该被拦截、"cd ../../etc"应该被阻止——这些常见危险操作需要应用层自己写规则。下一版本会提供默认的安全规则集。

#### 上下文压缩

对话太长时，模型装不下全部历史，需要压缩。就像人类做长项目时会写摘要——保留关键信息，丢弃闲聊。

**已有**：自动检测上下文超限，触发压缩，保留最近的对话+生成历史摘要。
**缺失**：
- 压缩用的提示词是硬编码的，不能自定义。下一版本会支持自定义压缩策略。
- 压缩失败时直接终止，没有重试。如果 API 暂时故障，整个 Agent 就停了。下一版本会加熔断器（连续失败几次才停止）。
- 不能标记某些消息"不可压缩"（比如关键决策、用户指令）。下一版本会支持。

#### 状态栏

Agent 运行时，用户想看到当前状态：在做什么、花了多少钱、还剩多少预算、有没有待处理的任务。

**已有**：运行时有注入机制，可以把状态信息附加到模型的上下文里。
**缺失**：没有默认的状态栏格式。应用层要自己写"收集哪些信息、怎么排版"。下一版本会提供开箱即用的状态栏模板。

#### 审计日志

Agent 做了什么操作、调了什么工具、花了多少钱——这些需要记录留痕。

**已有**：审计框架完整，记录带 SHA-256 哈希链，防篡改。
**缺失**：没有默认的结构化日志格式。应用层要自己定义日志长什么样。下一版本会提供默认模板。

#### 子 Agent

**已有**：派生、通信、查询、中止功能完整。
**缺失**：
- 子 Agent 不自动继承父 Agent 的系统提示词、工具列表和思考模式。每个子 Agent 要重新配置，容易遗漏。下一版本会支持配置继承。
- 查询子 Agent 状态时不返回它的角色描述。主 Agent 不知道某个子 Agent 是"代码审查员"还是"测试运行者"。下一版本会补上。

#### MCP 集成

MCP（Model Context Protocol）是一个开放协议，让 Agent 连接外部工具服务（如 GitHub、数据库、文件系统等）。

**已有**：基本可用——Agent 可以通过 MCP 协议调用外部工具。
**缺失**：
- 不锁定 MCP 服务器版本，服务器静默更新可能改变工具行为。下一版本会加版本锁定。
- 没有最小权限凭证管理。Agent 拿到的 API Key 能访问什么全靠人工配置。下一版本会加凭证作用域。
- 不审查 MCP 工具的描述文本（可能包含提示注入）。下一版本会加审查机制。

#### Skill 系统

Skill 是预定义的能力包——一段提示词 + 配套工具，让 Agent 快速获得某个领域的能力（比如"搜索网页"或"操作数据库"）。

**已有**：Skill 的加载、解析、读取工具都实现了。
**缺失**：没有自动把 Skill 列表注入到模型上下文的默认实现。模型不知道自己有哪些 Skill 可用。下一版本会提供默认注入。

#### 事件驱动

有些 Agent 不是一直运行的，而是等事件触发（比如"收到邮件时处理"、"每小时检查一次"）。

**已有**：事件流接口和等待工具都实现了，支持超时。
**缺失**：
- 没有默认的事件过滤规则（比如"只处理标记为紧急的邮件"）。下一版本会提供。
- 没有内置的定时器/心跳实现。应用层要自己写 Cron 逻辑。下一版本会提供。

#### 故障恢复

Agent 运行中会遇到各种故障：API 超时、工具报错、上下文损坏、无限循环。

**已有**：API 级别的重试和退避完整。
**缺失**：
- 重试等待没有随机抖动，多个 Agent 同时重试会"惊群"。下一版本会加。
- 流式输出时没有空闲检测。如果模型卡住不输出，Agent 会一直等。下一版本会加看门狗。
- 工具调用的轨迹可能不完整（模型输出了工具调用但没有结果）。下一版本会自动修复。
- 没有连续失败计数器。同一个工具连续失败 N 次应该换策略。下一版本会加。
- 没有死亡螺旋防护。Agent 进入错误循环时会反复调用 LLM 试图修复，越改越错。下一版本会加防护。
- 没有全局轮数上限。Agent 可能无限循环。下一版本会加 max_turns。

#### 提示工程与注入防御

Agent 的上下文里混着多种来源的内容：用户指令、工具返回结果、子 Agent 报告。恶意内容可能藏在工具返回里，误导 Agent。

**已有**：运行时有上下文注入接口。
**缺失**：
- 上下文注入时没有结构化的来源标注。模型分不清哪段是用户指令、哪段是工具返回。下一版本会给每段内容打来源标签。
- 没有默认的来源约束策略（比如"工具返回内容不能包含指令"）。下一版本会提供。

#### 项目指令文件

很多 AI Agent 项目用 `CLAUDE.md`、`.cursorrules` 等文件存放项目特定的指令（比如"用 Rust 写代码"、"测试用 pytest"）。Agent 启动时应该自动读取这些文件。

**已有**：运行时有启动前 Hook，可以注入内容到系统提示词。
**缺失**：没有自动扫描和读取项目指令文件的默认实现。下一版本会提供。

#### 写入后 lint

Agent 写完代码后，自动跑 linter 检查格式问题，如果有问题自动修复。

**已有**：运行时有"工具调用后 Hook"，支持替换工具输出。
**缺失**：没有内置的 lint 实现。下一版本暂不计划内置，但应用层可以基于现有 Hook 自己实现。

### 🔴 待实现

#### 搜索工具（grep + glob）

Agent 在大型代码库里找东西时，需要搜索工具：
- **grep**：按内容搜索（"找到所有包含 TODO 的文件"）
- **glob**：按文件名模式搜索（"找到所有 .rs 文件"）

当前 Agent 只能靠 bash 跑 `grep`/`find` 命令，但不同操作系统的行为有差异，且没有安全限制。下一版本会提供跨平台的专用搜索工具。

#### TODO 工具

Agent 执行多步骤任务时，需要维护待办列表——记录还剩什么没做、什么正在做、什么做完了。类似人类的 checklist。

当前运行时没有内置的 TODO 工具。Agent 只能把待办事项写在上下文里，容易在压缩时丢失。下一版本会提供。

#### HITL（人机协作）

有些操作需要人类确认后才能执行（"可以删除这个文件吗？"），有些需要人类提供输入（"这个变量叫什么名字？"）。

当前运行时没有内置的人机协作工具。应用层可以基于工具审批 Hook 自己实现，但没有开箱即用的方案。下一版本会提供 `request_human_approval` 和 `request_human_input` 两个内置工具，支持超时自动降级（没人响应时按默认策略处理）。

#### 通知

Agent 需要通知用户重要事件："任务完成了"、"遇到错误需要你看看"、"预算快用完了"。

当前运行时没有通知通道抽象，也没有 `notify_user` 工具。Agent 只能通过工具返回值间接传达信息。下一版本会加通知通道接口和默认实现。

#### 主动工具发现

当工具数量很多时（几十甚至上百个），全量塞给模型会导致提示词过长、模型选择困难。

当前运行时全量注入所有工具描述。下一版本会加 `discover_tools` 元工具——Agent 先搜索可用工具，只加载相关的。但短期内（数十个工具）全量注入仍然够用。

#### 持久化终端会话

Agent 跑 bash 命令时，每条命令都是独立的——`cd /tmp` 在下一条命令里不生效。要维持会话状态（当前目录、环境变量），需要持久化终端。

当前运行时每次执行 `sh -c` 新建进程。持久化终端需要 PTY 管理和长运行 shell 进程，实现复杂。暂不计划实现。

#### 流式工具执行

当前 Agent 等模型把整条回复全部生成完，才开始执行工具。如果模型在一条回复里调了多个工具，要等全部生成完才能执行第一个。

流式工具执行可以在模型生成到工具调用时立即开始执行，减少等待。但实现复杂（需要流中增量解析工具调用），暂不计划实现。

## 明确不做的事

| 不做 | 理由 |
|------|------|
| 流式工具执行 | 实现复杂度高，收益有限。当前"生成完再执行"的模式对大多数场景够用 |
| 持久化终端会话 | 需要 PTY 和长运行进程管理，复杂度高且安全风险大 |
| 写入后自动 lint | 运行时提供机制（Hook），但不内置 linter。应用层可自行接入 |
| 动态工具描述 + KV Cache 优化 | 当前数十个工具全量注入足够，优化收益不明 |
| 中途转向（mid-turn steer） | 有意选择同步循环模型——简单且匹配模型的训练方式 |
| 优先级消息队列 | 太复杂，当前消息按序处理足够 |
| 多渠道通知 | 先做单通道通知，多渠道（邮件+短信+IM）是应用层的事 |
