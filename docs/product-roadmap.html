📦 当前 v1.0.4 → 🎯 目标 v2.0

Senza 是 oh-my-harness Rust runtime 的 Python SDK——一个 AI Agent 的"操作系统"。

大语言模型只会对话，不能执行命令、读写文件、调用外部 API。Senza 给模型装上手脚和眼睛，让它变成能完成实际任务的 Agent。你可以把它想象成一个工作台：模型是坐在工作台前思考的人，工具是工作台上的器械，运行时是工作台本身——管理工具怎么摆放、安全围栏怎么设、上下文怎么传递、多个 Agent 怎么协作。

运行时不包含任何特定领域的逻辑，只提供通用基础设施。具体怎么用，由上层应用决定。

🟢 已可使用

功能做什么状态
Agent 核心循环Agent 按"思考→调用工具→看结果→再思考"循环工作。支持失败自动重试（指数退避）、流式输出、随时中止/取消✅
工作流引擎复杂任务拆成多阶段工作流，支持条件跳转、循环重试、崩溃后从断点恢复✅
文件编辑Agent 可以读文件（按行范围+行号）、编辑文件（行号定位+防过时检测）、写入文件✅
工具系统注册自定义工具，Agent 自动发现并使用。支持并行执行、输出投影（大结果只给模型看摘要）✅
并行工具执行同一轮里多个独立工具调用并行执行，不串行等待✅
沙箱隔离Agent 执行命令时安全隔离，限制文件访问和系统调用。Linux 用 bubblewrap，macOS 用 seatbelt✅
成本与预算自动记录每次 API 调用的 token 消耗和 USD 成本，支持预算上限（超限自动停止），按模型分别统计✅
子 Agent 协作主 Agent 可以派生子 Agent 分配独立任务，互相通信、等待回复、查询状态、中止子任务✅
持久状态任务执行记录可保存到磁盘，关键节点存检查点，进程崩溃后可恢复✅
规划能力Agent 可以先生成结构化计划，再按计划分步执行，根据结果调整后续步骤✅
Abort/取消用户或程序可随时中止运行，中止信号传播到所有子任务。有 3 个检查点保证安全取消✅

🚫明确不做的事

以下经讨论确认不在 runtime 职责内，或实现复杂度过高暂不实现。
不做理由
流式工具执行实现复杂度高（需在流中增量解析工具调用），当前"生成完再执行"的模式对大多数场景够用
持久化终端会话需要 PTY 和长运行进程管理，复杂度高且安全风险大
写入后自动 lint运行时提供机制（Hook），但不内置 linter。应用层可自行接入
动态工具描述 + KV Cache 优化当前数十个工具全量注入足够，优化收益不明
中途转向 (mid-turn steer)有意选择同步循环模型——简单且匹配模型的训练方式
优先级消息队列太复杂，当前消息按序处理足够
多渠道通知先做单通道通知，多渠道（邮件+短信+IM）是应用层的事

🚀v2.0 交付后意味着什么

八个维度，逐一看 2.0 完成后的实际能力跃升。
维度1.0 现状2.0 目标
开箱即用 框架完整但需大量配置：安全规则、状态栏、审计格式、压缩策略、Skill 注入都要应用层从零实现 零配置即可安全运行。默认安全规则、状态栏、审计日志、压缩策略、项目指令注入、Skill 列表全部开箱即用。用户装上 SDK、写三行代码就能跑一个安全的 Agent
安全防护 有审批框架但没有默认规则，bash 和文件操作依赖应用层自行防护 三层防线完整：命令语义分析（不只是字符串匹配）+ 危险命令黑名单 + 路径遍历防护。Agent 执行任何危险操作前自动拦截，不需要开发者写一行安全代码
人机协作 无内置工具，应用层要基于审批框架自己实现确认和输入流程 request_human_approval 和 request_human_input 两个内置工具，支持超时自动降级（没人响应时按安全策略处理）。Agent 能自主判断何时需要人类介入，并优雅处理无人响应的场景
故障韧性 API 重试完整，但工具级故障（连续失败、循环调用、上下文损坏）无防护 六层故障防护：退避抖动防惊群、空闲看门狗防卡死、轨迹修复防上下文损坏、连续失败计数防重试浪费、死亡螺旋防护防错误扩大、全局 max_turns 防无限循环。Agent 在各种异常场景下都能安全降级而非崩溃
上下文管理 压缩基础设施完整但 prompt 硬编码、无熔断、关键消息可能被丢弃 压缩全链路可控：自定义压缩策略、连续失败熔断（API 偶尔故障不终止 Agent）、关键消息不可压缩标记、上下文来源标注防注入。长任务不会因压缩丢失关键信息，也不会因压缩失败而中断
工具生态 有 bash/read/write/edit 四个工具，搜索靠 bash 命令，无通知/HITL/发现机制 工具体系完整：跨平台 grep+glob 搜索工具、notify_user 通知工具、HITL 工具、discover_tools 按需加载、工具层次化组织。Agent 的"工具箱"从 4 件扩展到 10+ 件，覆盖搜索、通知、确认、发现全链路
子 Agent 协作 派生/通信/中止完整，但子 Agent 不继承配置，查询不返回角色 子 Agent 自动继承父 Agent 的系统提示词、工具列表和思考模式，减少配置遗漏。查询时返回角色描述，主 Agent 清楚每个子 Agent 的职责。多 Agent 协作从"能用"提升到"好用"
架构清晰度 策略代码混在机制层 crate 中，边界靠开发者纪律维护 策略代码全部在独立 crate 中，编译器强制边界——策略代码只能用公开 API，不能伸手到内部实现。"机制层能做的不放机制层"从设计原则变成编译器保证。代码更易维护、更易测试、更易贡献

一句话总结

1.0 是一个框架完整但需大量配置的运行时——所有机制都在，但安全规则、状态栏、审计格式、压缩策略都要应用层自己写。

2.0 是一个零配置安全可用的运行时——装上就能跑，默认安全规则、故障防护、人机协作、通知、搜索工具全部内置。开发者只需关注业务逻辑，不再需要重复造安全围栏和运维基础设施的轮子。
