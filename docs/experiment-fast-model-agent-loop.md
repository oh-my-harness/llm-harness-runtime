目标不变。当前执行基准见第 0 节；下文第 2–4 节保存上一轮 TypeScript jev-browser 适配条件，不再作为作者 v19s 路线的运行配置。MiniWoB++ 保持撤下。

决策模型必须直接推进任务，不只决定“要不要调用大模型”。框架负责观测和执行，独立验收器判定质量；模型输出 DONE 不等于任务成功。

| 分工 | A：Qwen 决策与生成 | B：Laya 决策 + Qwen 按需生成 |

| 动作与目标 | Qwen | Laya |
| 填写文本 | 同一个 Qwen | 同一个 Qwen，仅在选定填写动作和目标后调用 |
| 观测、候选、工具与框架 | 相同引擎与可见信息 | 相同引擎与可见信息 |
| 初始状态与质量判定 | 配对初态、相同独立验收 | 配对初态、相同独立验收 |

不为放大速度差而强制 A 将可一次返回的动作、目标和文本拆成多次请求。原版基线若采用不同调用结构，必须先说明差异，再决定严格复现还是合理适配；不得悄悄改变。

候选来自真实环境，禁止任务专用规则代选、隐藏正确答案、提前写好操作序列。Laya 的输入表达、上下文预算、实际前向及映射必须审计，截断或适配失败如实记录。模型权重、量化、回退策略等变更需单独确认。

两组共享权限、动作/时间预算及可比的重试策略；按任务与重复轮次配对，平衡运行顺序，隔离浏览器上下文。公共网站的内容漂移及网络条件必须记录，不能假定每次初态完全相同。最终验收同时要求原始任务页面的主文档 HTTP 状态非错误；URL 正确但返回错误页面不算成功。

不自动增加普通 LLM 工具循环第三组。旧 MiniWoB 的 12 对、120 秒和模型输入预算不自动继承到新任务。

已确认任务为 `shadow-dom`、`nested-scroll`、`cross-origin-iframe`、`select`、`wikipedia`、`hacker-news`、`mdn`，来源均为固定版本 `examples/journeys.ts`。[运行清单](../configs/research/jev-browser-preparation.json)保存来源、批准范围、模型选择和运行条件。独立验收已固定 Hacker News 初始头条 ID、MDN 精确目标路径及 Wikipedia 主机/路径检查，同时保留上游原判定；不向模型提供验收答案。

## 5. 必须记录的量化数据

| 指标 | 口径 |
| --- | --- |
| 完整任务通过率 | 独立验收通过数 / 全部已执行尝试；超时、错误、预算耗尽保留在分母。另列未执行项，报告独立任务数和每题重复数 |
| 端到端耗时 | 从发出任务开始到最终验收结束的墙钟时间，包含模型、网络、观测、候选、工具、等待、恢复和重试；另记上游 run.elapsedMs 以便核对口径 |
| 耗时分布 | 全部尝试、成功和失败分别报告均值、中位数、p95；小样本只作描述 |
| 有效配对速度 | 双方均成功配对中 sum(A 耗时) / sum(B 耗时)，同时给出覆盖数；无成功配对则不适用。失败更早不是有效提速 |
| 调用次数 | 大模型按生成、决策、混合互斥计数；记录逻辑调用、实际 HTTP 尝试、SDK/应用重试、错误、token 和耗时。Laya 另记决策问题数、批量与实际前向次数 |
| 工具与框架 | 工具次数及耗时、观测/候选处理、验收、缓存命中和恢复成本；阶段并行时不将累加值误当墙钟时间 |
| 质量差异 | B-A 通过率百分点差；双方通过、仅 A 通过、仅 B 通过、双方失败的配对数和逐题失败原因 |
| 失败成本 | 全部尝试累计耗时 / 成功数，零成功记不适用；同时报告全量及双方成功子集的大模型调用变化，防止提前失败造成虚假节省 |

模型加载、预热、浏览器准备、清理和整场墙钟另列；任务中发生的加载不能从端到端用时扣掉。GPU 计时等待计算完成，远程调用保留网络等待，异常路径也记结束事件，未知 token 不填零。

记录代码与任务版本、模型/checkpoint、设备、精度、上下文、输出预算、服务端点类别、并发与顺序；服务端未知条件标为未知。保留脱敏逐次数据，不记录密钥。

“相近质量”的容忍差值、正式样本量及统计方法在运行前确认。不得仅凭几个成功案例或不显著差异宣布等价；正式分析按独立任务成组保留重复与配对，报告不确定性。
